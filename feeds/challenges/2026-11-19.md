TITLE: Session Context Merger
DIFFICULTY: Medium
TOPIC: Hash Maps & Sets
ESTIMATED_TIME: 25 minutes

PROBLEM:
You are building a backend service that aggregates user interaction logs from multiple independent browser tabs into a single unified session history. Each tab sends an array of log entries, but due to network jitter, entries can arrive out of order, be duplicated, or overlap in time.

You are given a list of log arrays (`tabs`), where each log entry is represented as an object (or dictionary) containing:
- `timestamp`: An integer representing millisecond epoch time.
- `action`: A string representing the user's action (e.g., "click", "scroll", "input").
- `target`: A string representing the UI element identifier.

Write a function `mergeSessionLogs(tabs)` that merges all log arrays into a single chronologically sorted list. 
If two or more log entries across different tabs have the **exact same `timestamp`**, `action`, and `target`, treat them as duplicates and keep only one instance. 
Additionally, if entries have the exact same `timestamp` but different actions/targets, sort them deterministically by `action` (alphabetically), and then by `target` (alphabetically).

EXAMPLES:
Input: 
tabs = [
  [
    {"timestamp": 100, "action": "click", "target": "btn-submit"},
    {"timestamp": 105, "action": "input", "target": "field-email"}
  ],
  [
    {"timestamp": 100, "action": "click", "target": "btn-submit"},
    {"timestamp": 102, "action": "scroll", "target": "page-body"}
  ]
]
Output: 
[
  {"timestamp": 100, "action": "click", "target": "btn-submit"},
  {"timestamp": 102, "action": "scroll", "target": "page-body"},
  {"timestamp": 105, "action": "input", "target": "field-email"}
]
Explanation: The duplicate entry at timestamp 100 is removed. The remaining entries are sorted chronologically by timestamp.

Input: 
tabs = [
  [{"timestamp": 50, "action": "view", "target": "dashboard"}],
  [{"timestamp": 50, "action": "click", "target": "nav-home"}]
]
Output: 
[
  {"timestamp": 50, "action": "click", "target": "nav-home"},
  {"timestamp": 50, "action": "view", "target": "dashboard"}
]
Explanation: Both entries share the same timestamp (50). They are sorted lexicographically by action ("click" before "view").

CONSTRAINTS:
- `tabs` contains between 1 and 50 arrays.
- Each array contains between 0 and 1,000 log entries.
- `timestamp` is a non-negative integer up to $10^{13}$.
- `action` and `target` are non-empty strings of length up to 50.

HINT:
Use a Hash Set to store unique composite keys (combining timestamp, action, and target) to eliminate duplicates in $O(1)$ average time per entry. Then, sort the unique entries.

SOLUTION_PYTHON:
```python
def mergeSessionLogs(tabs):
    seen = set()
    unique_logs = []
    
    for tab in tabs:
        for log in tab:
            # Create a unique tuple signature for deduplication
            signature = (log["timestamp"], log["action"], log["target"])
            if signature not in seen:
                seen.add(signature)
                unique_logs.append(log)
                
    # Sort primarily by timestamp, then action, then target
    unique_logs.sort(key=lambda x: (x["timestamp"], x["action"], x["target"]))
    
    return unique_logs
```

SOLUTION_JS:
```javascript
function mergeSessionLogs(tabs) {
    const seen = new Set();
    const uniqueLogs = [];

    for (const tab of tabs) {
        for (const log of tab) {
            // Create a unique string signature for deduplication
            const signature = `${log.timestamp}|${log.action}|${log.target}`;
            if (!seen.has(signature)) {
                seen.add(signature);
                uniqueLogs.push(log);
            }
        }
    }

    // Sort primarily by timestamp, then action, then target
    uniqueLogs.sort((a, b) => {
        if (a.timestamp !== b.timestamp) {
            return a.timestamp - b.timestamp;
        }
        if (a.action !== b.action) {
            return a.action.localeCompare(b.action);
        }
        return a.target.localeCompare(b.target);
    });

    return uniqueLogs;
}
```

TIME_COMPLEXITY: $O(N \log N)$ where $N$ is the total number of log entries across all tabs, dominated by the sorting step. Deduplication takes $O(N)$ time.
SPACE_COMPLEXITY: $O(N)$ to store the set of unique signatures and the resulting array of unique logs.

EXPLANATION:
We flatten the multi-dimensional array of tabs while using a Hash Set to track unique log signatures (`timestamp`, `action`, `target`). This ensures absolute deduplication in linear time relative to the total number of entries. Once duplicates are filtered out, we perform a multi-criteria sort on the deduplicated collection, handling chronological order first, followed by deterministic alphabetical tie-breakers for actions and targets.
