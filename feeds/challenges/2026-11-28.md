PROBLEM:
You are building a time-sensitive caching layer for a high-frequency trading platform. The system ingests a chronological stream of cache operations. Each operation can be an insertion of a key-value pair with a specific "vitality" score, an expiration of time, or a query to fetch the *active median vitality score* across a sliding window of recent operations.

However, the cache operates under strict rules:
1. **Insert (P, V)**: Insert a key with Priority `P` and Vitality `V` at the current logical timestamp `T`.
2. **Expire (W)**: All items whose insertion timestamp is strictly less than `T - W` are immediately evicted from the cache.
3. **Median Query**: Return the median vitality of all *currently active* items in the cache. If the number of active items is even, return the floor of the average of the two middle elements. If no items are active, return `-1`.

You are given an array of operations. Implement a data structure that processes these operations efficiently.

Operations format:
- `[1, timestamp, priority, vitality]`: Insert
- `[2, timestamp, window]` : Expire items older than `timestamp - window` (Note: `timestamp` is strictly monotonically increasing).
- `[3, timestamp]` : Query the median vitality of active items.

EXPLANATION:
To solve this efficiently, we leverage the **Dual-Heap Pattern** (a max-heap for the lower half of vitalities and a min-heap for the upper half) to maintain the median in $O(1)$ time. Because items must expire based on chronological timestamps, a queue tracks the arrival time of each vitality score. When an expiration operation occurs, expired elements are marked for lazy deletion and removed from the heaps dynamically, ensuring the median always reflects the active window of the cache.
