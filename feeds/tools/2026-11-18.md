# LiteLLM

**Category:** AI/LLM

[![Repo](https://img.shields.io/badge/View_on_GitHub-181717?style=flat-square&logo=github)](

---

## What Is It?
LiteLLM is a lightweight Python SDK and proxy server that provides a unified, OpenAI-compatible API for over 100 different Large Language Models. It abstracts away the endless provider-specific SDKs, API keys, and rate-limit formats into a single interface.

## The Problem It Solves
Switching from OpenAI to Anthropic, Cohere, or an open-source model hosted on Together AI usually means rewriting your API integration, changing your payload structures, and managing a dozen different SDKs. Developers waste hours wrestling with provider-specific quirks, setting up redundant failover logic, and tracking API spend across multiple dashboards. LiteLLM acts as a single translation layer, letting you swap out `gpt-4` for `claude-3-opus` by changing just a single string in your code.

## Why It's Worth 10 Minutes of Your Time
* **Drop-in OpenAI Replacement:** Because it mimics the OpenAI format, you can plug LiteLLM directly into existing tools like LangChain, LlamaIndex, or AutoGen without rewriting your stack.
* **Built-in Load Balancing & Fallbacks:** If OpenAI goes down or hits a rate limit, the LiteLLM proxy can automatically reroute your requests to Anthropic or a backup model with zero downtime.
* **Unified Cost & Budget Tracking:** It comes with out-of-the-box spend tracking, allowing you to set hard budget limits per API key, team, or user across all connected providers.

## Quick Start
```bash
pip install litellm
```
```python
import os
from litellm import completion

# Set keys for whichever providers you want to use
os.environ["OPENAI_API_KEY"] = "your-openai-key"
os.environ["ANTHROPIC_API_KEY"] = "your-anthropic-key"

# Call Claude just like you would call GPT-4
response = completion(
    model="anthropic/claude-3-5-sonnet-20241022",
    messages=[{"role": "user", "content": "Hello from LiteLLM!"}]
)
print(response.choices[0].message.content)
```

## Real-World Example
```python
# Setting up automatic fallbacks for production reliability
from litellm import completion

response = completion(
    model="gpt-4o",
    # If OpenAI fails or rate-limits, instantly try Claude, then fallback to local Llama3
    fallbacks=["claude-3-5-sonnet-20241022", "ollama/llama3"],
    messages=[{"role": "user", "content": "Analyze this data..."}]
)
```

## Who Should Use It
✅ Perfect for: Teams building LLM apps who want multi-provider support, built-in failover, budget management, and zero vendor lock-in.
⏩ Skip if: You are strictly tethered to a single provider (e.g., only using OpenAI) and never plan to use open-source or competing models.

## The Honest Take
LiteLLM is a massive time-saver for multi-model architectures, though running its proxy server in production adds another infrastructure piece to monitor. Bottom line: if you're tired of rewriting API clients every time a better model drops, this is an absolute must-try.
