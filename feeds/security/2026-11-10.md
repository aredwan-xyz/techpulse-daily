### 🛡️ Maintenance Focus: Proactive Security Checks

Since there are no fresh CVEs to patch today, use this time to perform proactive repository hygiene:

1. **Run Local Lockfile Audits:** Execute your package manager’s audit tool (`npm audit`, `pip-audit`, `cargo audit`, or `govulncheck`) to ensure no recent secondary vulnerabilities slipped into your builds.
2. **Scan for Hardcoded Secrets:** Run a scanner like `gitleaks` or `trufflehog` across recent branches to ensure API keys, private certificates, or tokens weren't accidentally committed.
3. **Review Third-Party Actions & Pipeline Plugins:** Inspect your CI/CD pipelines (e.g., GitHub Actions, GitLab CI) and pin external actions to specific full-length commit SHAs rather than mutable tags (like `@v2`).

---

### 💡 Security Mindset: Default to Least Privilege

**Never request or grant more access than the immediate task requires.** 

Whether you are configuring a database user, creating an IAM role for a microservice, or requesting an API token, restrict permissions strictly to what is necessary for normal operation. If a background job only needs to read from a single table, connect it using a read-only user restricted to that specific table. If a compromise occurs, limiting scope minimizes the blast radius.
