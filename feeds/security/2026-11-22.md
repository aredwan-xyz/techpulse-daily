### 🛡️ General Security Guidance (NVD Downtime Fallback)

When primary upstream feed sources like NVD experience downtime, rely on local tooling and secondary feeds to maintain visibility over your software supply chain:

1. **Run Local Dependency Audits:** Do not wait for NVD alerts. Execute built-in ecosystem scanners in your CI/CD pipelines today:
   * **Node.js:** `npm audit` / `pnpm audit` / `yarn audit`
   * **Python:** `pip-audit`
   * **Rust:** `cargo audit`
   * **Go:** `govulncheck ./...`
2. **Check Secondary Advisories:** Review the [GitHub Security Advisory Database (GHSA)](https://github.com/advisories) or OS-specific security tracker feeds (e.g., Debian, Alpine, RedHat) for actionable vulnerability data published by maintainers directly.
3. **Verify Lockfiles:** Ensure all project dependencies are pinned to explicit versions and lockfiles (`package-lock.json`, `poetry.lock`, `Cargo.lock`) are up to date and committed to source control to prevent unexpected upstream dependency updates.

### 💡 Security Mindset Tip

**Practice "Never Trust, Always Sanitize" at Boundary Interfaces**

Treat *every* external data source — whether it's a URL parameter, a database response, an HTTP header, or an third-party API payload — as potentially hostile. Validate inputs against strict allowlists (type, length, format) immediately upon entry, and contextual-encode outputs right before rendering or sending them to another system.
