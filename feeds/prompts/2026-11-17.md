PROMPT_TITLE: Precision PRD Generator

THE_PROMPT:
Act as a Principal Product Manager. Write a comprehensive, developer-ready Product Requirements Document (PRD) for `{FEATURE_NAME}`.

**Context:**
- **Target User:** `{TARGET_USER}`
- **Problem Statement:** `{PROBLEM_STATEMENT}`
- **Business Goal:** `{BUSINESS_GOAL}`
- **Core Capabilities Desired:** `{KEY_CAPABILITIES}`
- **Constraints & Dependencies:** `{CONSTRAINTS_DEPENDENCIES}`

**Structure the PRD into these sections:**
1. **Executive Summary:** High-level vision and "Why Now".
2. **User Stories & Acceptance Criteria:** Write 3-5 core user stories using standard "As a... I want to... So that..." format, each with explicit Given/When/Then acceptance criteria.
3. **Functional Requirements:** Categorized priority list (Must-Have vs. Nice-to-Have) with edge cases identified.
4. **Non-Functional Requirements:** Specific performance, security, accessibility (e.g., WCAG 2.1 AA), and scalability metrics.
5. **Out of Scope:** Explicitly list what this iteration will NOT include to prevent scope creep.
6. **Success Metrics (KPIs):** Quantifiable outcomes directly tied to `{BUSINESS_GOAL}`.
7. **Open Questions & Risks:** Technical or UX blockers needing engineering/design alignment.

Maintain a crisp, objective, and technical tone. Avoid vague language like "fast" or "user-friendly"—use measurable benchmarks instead.

WHEN_TO_USE:
Use this prompt when transitioning a feature from high-level concept to technical execution. It generates a standardized, developer-ready specification that bridges the gap between product strategy, engineering, and design. Perfect for kickoff alignment, sprint planning, or getting stakeholder sign-off.

EXAMPLE_INPUT:
- `{FEATURE_NAME}`: One-Click Wallet Checkout
- `{TARGET_USER}`: Mobile web shoppers making impulse purchases
- `{PROBLEM_STATEMENT}`: 68% cart abandonment rate on mobile due to tedious multi-step billing and shipping forms.
- `{BUSINESS_GOAL}`: Increase mobile conversion rate by 15% and cut average checkout completion time under 20 seconds.
- `{KEY_CAPABILITIES}`: Native Apple Pay & Google Pay support, auto-address hydration from digital wallet, dynamic tax/shipping calculation, guest fallback flow.
- `{CONSTRAINTS_DEPENDENCIES}`: Must comply with PCI-DSS Level 1; integration relies on Shopify Plus Checkout Sheet API.

EXAMPLE_OUTPUT_SUMMARY:
Produces a complete, professional PRD formatted with Markdown headers and bullet points. It includes Gherkin-style acceptance criteria (Given/When/Then), explicit non-functional benchmarks (e.g., tokenized payload processing in <600ms), and a clear "Out of Scope" list that keeps engineers focused strictly on the MVP scope.

PRO_TIPS:
- Include existing tech stack details in `{CONSTRAINTS_DEPENDENCIES}` to get tailored architectural and security requirements.
- After receiving the PRD, follow up with: "Generate 5 specific edge cases for section 3 that could break this workflow."
- Copy-paste the generated User Stories directly into Jira, Linear, or Azure DevOps as backlog epics.
