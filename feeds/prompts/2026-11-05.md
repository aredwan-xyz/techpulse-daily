PROMPT_TITLE: AI-Assisted Scalable System Architect

THE_PROMPT:
Act as a Principal Distributed Systems Architect. Design a scalable, fault-tolerant system architecture for: {PROJECT_DESCRIPTION}.

Key Constraints & Requirements:
- Expected Scale: {DAILY_ACTIVE_USERS} DAU, peak traffic of {PEAK_QPS} QPS.
- Tech Stack Preferences: {TECH_STACK}.
- Core Non-Functional Requirements: {NFRS, e.g., <50ms latency, 99.999% availability, strict GDPR compliance}.
- Budget / Infrastructure Constraints: {CONSTRAINTS}.

Provide a comprehensive system design document structured as follows:
1. **High-Level Architecture**: Describe the core components and data flow. Include an ASCII or Mermaid.js sequence/architecture diagram.
2. **Data Storage & Management**: Choose databases/caches (SQL vs. NoSQL) with justification, sharding/partitioning strategies, and caching layers.
3. **Scalability & Performance**: Explain how the system handles load balancing, horizontal scaling, auto-scaling triggers, and bottleneck mitigation.
4. **Reliability, Fault Tolerance & Security**: Detail disaster recovery, multi-region failover, backup strategies, data encryption, and rate limiting/auth.
5. **Trade-offs & Alternatives**: Outline at least two major architectural decisions made, why they were chosen, and what alternatives were rejected.

WHEN_TO_USE:
Use this prompt when you need to architect a new software system, service, or feature from scratch and require a rigorous, production-grade blueprint that anticipates scale, bottlenecks, and failure modes.

EXAMPLE_INPUT:
- PROJECT_DESCRIPTION: Real-time collaborative document editor like Google Docs
- DAILY_ACTIVE_USERS: 5,000,000 DAU
- PEAK_QPS: 50,000 writes/sec, 200,000 reads/sec
- TECH_STACK: Node.js, Redis, PostgreSQL, Kafka, AWS
- NFRS: Sub-100ms operational transform/CRDT sync latency, 99.99% uptime
- CONSTRAINTS: Must fit within AWS free-tier during dev, scalable to enterprise budget in production

EXAMPLE_OUTPUT_SUMMARY:
This prompt produces an enterprise-grade system design document complete with a Mermaid architecture diagram, database schema partitioning plans, CRDT-based conflict resolution strategies, and a clear breakdown of architectural trade-offs.

PRO_TIPS:
- Specify exact compliance regulations (e.g., HIPAA, SOC2) in the NFRs section if handling sensitive data.
- Adjust the PEAK_QPS to stress-test the AI's recommendations for caching and message queues (like Kafka or RabbitMQ).
- Ask the AI to elaborate on specific sections (e.g., "Deep dive into the database sharding strategy in section 2") as a follow-up prompt.

WORKS_WITH: Claude · GPT-4 · Gemini
