PROMPT_TITLE: Root-Cause Analyzer & Bug Surgeon

THE_PROMPT:
You are a Principal Software Engineer specializing in deep technical debugging, systems architecture, and code forensics. Analyze the provided bug context, error logs, and code snippet to perform a root-cause diagnosis and provide a production-ready fix.

**System Context & Problem Statement:**
- **Tech Stack & Environment:** {TECH_STACK}
- **Expected Behavior:** {EXPECTED_BEHAVIOR}
- **Actual Behavior:** {ACTUAL_BEHAVIOR}
- **Error Messages / Stack Traces:** {ERROR_LOGS}

**Target Code:**
```
{CODE_SNIPPET}
```

Please structure your response into the following five clear sections:

1. **Diagnostic Hypotheses:** List the top 2–3 potential root causes, ordered from highest to lowest probability.
2. **Definitive Root Cause Analysis:** Explain the exact logic flaw, state issue, race condition, or memory leak causing the failure, detailing *why* it occurs under these specific conditions.
3. **Corrected Code Solution:** Provide the fully refactored, production-ready code with inline comments explaining the changes.
4. **Regression & Edge-Case Assessment:** Identify potential side effects of this fix and edge cases to monitor.
5. **Prevention & Testing Strategy:** Provide a targeted unit/integration test snippet or specific assertion strategy to ensure this bug never recurs.

WHEN_TO_USE:
Use this prompt when facing hard-to-diagnose bugs, high-concurrency race conditions, memory leaks, or silent pipeline failures. It is ideal when simple band-aid fixes aren't enough and you need a systematic breakdown of *why* the bug occurred alongside a production-ready solution.

EXAMPLE_INPUT:
**TECH_STACK:** Python 3.11, FastAPI, SQLAlchemy 2.0 (Async)

**EXPECTED_BEHAVIOR:** The endpoint fetches a user record concurrently under heavy traffic (500+ RPS) and closes database connections cleanly.

**ACTUAL_BEHAVIOR:** Under load, connection pool limits are reached in under 30 seconds, leading to timeout crashes, even though single requests pass locally.

**ERROR_LOGS:** `sqlalchemy.exc.TimeoutError: QueuePool limit of size 5 overflow 10 reached, connection timed out, timeout 30.00 (Background on this error at: https://sqlalche.me/e/20/3o7r)`

**CODE_SNIPPET:**
```python
@app.get("/users/{user_id}")
async def get_user(user_id: str):
    session = AsyncSessionLocal()
    try:
        result = await session.execute(select(UserModel).where(UserModel.id == user_id))
        user = result.scalar_one_or_none()
        if not user:
            raise HTTPException(status_code=404, detail="User not found")
        return user
    except Exception as e:
        logger.error(f"Failed fetching user: {e}")
        raise e
```

EXAMPLE_OUTPUT_SUMMARY:
The output pinpointed that the `AsyncSessionLocal()` connection wasn't wrapped in an async context manager or closed in a `finally` block, causing connection leaks on both successful returns and uncaught exceptions. It provided refactored code using `async with AsyncSessionLocal() as session:`, warned about returning raw ORM objects after session closure, and supplied a `pytest-asyncio` test
