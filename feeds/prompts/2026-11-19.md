PROMPT_TITLE: Architect-Grade Scalable System Design

THE_PROMPT:
Act as a Principal Software Architect. Your task is to design a robust, scalable system for {SYSTEM_NAME} that must handle {EXPECTED_TRAFFIC} with a latency requirement of {LATENCY_TARGET}. 

Please provide a comprehensive technical blueprint covering the following pillars:
1. **High-Level Architecture**: Propose a topology (e.g., Microservices, Event-Driven, Serverless) and justify the choice based on the requirements.
2. **Data Strategy**: Recommend primary databases (SQL vs. NoSQL), caching layers, and partitioning strategies to ensure horizontal scalability.
3. **Resiliency & Scaling**: Detail your approach to load balancing, auto-scaling, fault tolerance, and disaster recovery.
4. **API & Communication**: Define the communication patterns (e.g., gRPC, REST, WebSockets, Message Queues) between core services.
5. **Trade-offs**: Create a "Decision Log" highlighting two critical technical trade-offs you made (e.g., CAP theorem considerations) and why they are acceptable for this system.

Ensure the design accounts for data consistency, security, and observability. Use technical diagrams (Mermaid syntax) where appropriate to visualize the data flow and system hierarchy.

WHEN_TO_USE:
Use this when you are in the initial design phase of a new feature or infrastructure overhaul. It is ideal for breaking down complex requirements into actionable technical specifications that can be handed directly to an engineering team.

EXAMPLE_INPUT:
{SYSTEM_NAME}: A real-time collaborative code editor similar to Google Docs.
{EXPECTED_TRAFFIC}: 50,000 concurrent active users.
{LATENCY_TARGET}: Under 100ms for character synchronization.

EXAMPLE_OUTPUT_SUMMARY:
The prompt produces a high-level technical document that includes a Mermaid diagram of the infrastructure, a detailed breakdown of the chosen tech stack (e.g., WebSockets for real-time, Redis for state, CRDTs for conflict resolution), and a critical analysis of performance bottlenecks. It creates a professional-grade roadmap that balances speed with consistency.

PRO_TIPS:
- If the system is data-heavy, follow up by asking: "Now, create a detailed database schema for the core {DATABASE_TYPE} service."
- Ask the AI to "identify the single point of failure in this architecture" after it provides the initial design to force a more resilient iteration.
- Specify your preferred tech stack (e.g., "Use AWS services and Go/Postgres") in the prompt if you have existing infrastructure constraints.
