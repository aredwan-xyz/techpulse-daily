PROMPT_TITLE: Senior Staff Engineer Code Reviewer

THE_PROMPT:
Act as a Staff Software Engineer conducting a thorough, constructive code review.

Context & Goal: {CONTEXT_OR_GOAL}  
Language & Stack: {LANGUAGE_OR_FRAMEWORK}  
Specific Focus/Concerns: {CONCERNS_OR_FOCUS_AREAS}

Code to Review:
```
{CODE_TO_REVIEW}
```

Please structure your review as follows:

1. **Executive Summary**: A 2-3 sentence high-level assessment of the code quality, clarity, and design.
2. **Critical Bugs & Security Vulnerabilities**: Highlight potential crashes, race conditions, memory leaks, security risks, or data corruption hazards.
3. **Performance & Scalability**: Identify inefficient algorithms, unnecessary re-renders/allocations, unindexed queries, or I/O bottlenecks.
4. **Edge Cases & Error Handling**: Point out unhandled exceptions, missing null/undefined checks, boundary conditions, or silent failures.
5. **Readability & Idiomatic Clean Code**: Suggest improvements for naming, modularity, type safety, and language-specific idioms.
6. **Refactored Code**: Provide the complete, production-ready refactored version of the code implementing your recommendations, with inline comments explaining major architectural or logic improvements.

Maintain a pragmatic, senior-level tone. Focus on high-impact improvements rather than subjective formatting nitpicks.

WHEN_TO_USE:
Use this prompt before submitting a Pull Request to catch bugs early, optimize critical functions, or learn language-specific best practices. It is ideal for self-reviews, refactoring legacy code, or validating security-sensitive logic.

EXAMPLE_INPUT:
{CONTEXT_OR_GOAL}: Express API route that updates user account balances and triggers an audit log entry.
{LANGUAGE_OR_FRAMEWORK}: Node.js / TypeScript with Prisma ORM
{CONCERNS_OR_FOCUS_AREAS}: Transaction safety, race conditions under heavy traffic, and proper error responses.
{CODE_TO_REVIEW}:
```typescript
app.post('/api/balance', async (req, res) => {
  const { userId, amount } = req.body;
  const user = await prisma.user.findUnique({ where: { id: userId } });
  if (!user) return res.status(404).json({ error: 'User not found' });

  const newBalance = user.balance + amount;
  await prisma.user.update({
    where: { id: userId },
    data: { balance: newBalance }
  });

  await prisma.auditLog.create({
    data: { userId, action: 'BALANCE_UPDATE', amount }
  });

  res.json({ success: true, balance: newBalance });
});
```

EXAMPLE_OUTPUT_SUMMARY:
Produces a structured breakdown identifying race conditions (lack of atomic update/database transaction) and missing request validation. It provides a copy-pasteable TypeScript refactor using `prisma.$transaction` and dynamic SQL increment logic to ensure data integrity under concurrent loads.

PRO_TIPS:
- Include existing unit tests in `{CODE_TO_REVIEW}` so the AI can verify if your edge cases are covered.
- State your performance requirements explicitly (e.g., "This function runs inside a tight loop with 10k items").
- If working with strict typing (e.g., Rust, TypeScript, C++), ask the AI to enforce strict type-safety checks.
