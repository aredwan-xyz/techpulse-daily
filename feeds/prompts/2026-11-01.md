PROMPT_TITLE: Clean Code & Cognitive Load Refactorer

THE_PROMPT:
Act as a principal software engineer specializing in software craftsmanship and clean code architecture. Refactor the following `{LANGUAGE}` code to maximize readability, minimize cognitive complexity, and ensure long-term maintainability, while strictly preserving its original runtime behavior and public API contract.

Code to refactor:
```{LANGUAGE}
{CODE_SNIPPET}
```

Context & Constraints:
- Coding standards/paradigms to prioritize: {STYLE_GUIDELINES_OR_PARADIGM}
- Known constraints or critical edge cases: {KNOWN_CONSTRAINTS}

Please structure your response as follows:
1. **Complexity Audit**: Briefly diagnose the top 3–4 code smells or friction points in the original snippet (e.g., deeply nested conditionals, high cyclomatic complexity, poor variable naming, side effects).
2. **Refactored Implementation**: Output the complete, idiomatic, and clean code. Apply principles like early returns/guard clauses, single responsibility, declarative expressions, and self-documenting names. Include clear docstrings/type annotations if standard in `{LANGUAGE}`.
3. **Key Improvements**: Provide a concise summary of the structural changes made and explain specifically why each refactoring choice improves maintainability for future developers.
4. **Safety Verification**: Highlight any subtle edge cases or side-effect behaviors you took care to preserve.

WHEN_TO_USE:
Use this prompt when preparing messy feature branches for pull request review, reducing technical debt in legacy codebases, or untangling deeply nested business logic before adding new features.

EXAMPLE_INPUT:
LANGUAGE: TypeScript
CODE_SNIPPET:
```typescript
function p(u: any, o: any) {
  if (u && u.active) {
    if (o && o.items && o.items.length > 0) {
      let t = 0;
      for (let i = 0; i < o.items.length; i++) {
        if (o.items[i].type == 1) {
          t += o.items[i].price * 0.9;
        } else if (o.items[i].type == 2) {
          t += o.items[i].price * 0.8;
        } else {
          t += o.items[i].price;
        }
      }
      if (u.tier == 'vip') {
        t = t - 10;
      }
      return t > 0 ? t : 0;
    } else {
      return 0;
    }
  } else {
    throw new Error('Invalid user');
  }
}
```
STYLE_GUIDELINES_OR_PARADIGM: Modern idiomatic TypeScript, functional style (array methods), guard clauses, strict type definitions, meaningful domain naming.
KNOWN_CONSTRAINTS: VIP discount cannot reduce the total below 0; items of unknown type receive no discount.

EXAMPLE_OUTPUT_SUMMARY:
The prompt delivers a fast critique of primitive obsession, magic numbers, and nested logic, followed by fully typed interfaces, guard clauses, and an array `.reduce()` pipeline. It concludes with a bulleted breakdown showing how the refactored code prevents silent failures and makes discount rules extensible.
