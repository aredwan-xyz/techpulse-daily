PROMPT_TITLE: Production-Ready Test Suite Generator

THE_PROMPT:
Act as a Principal QA & Software Engineer specializing in automated testing. Your task is to generate a comprehensive, production-ready test suite for the following code or functional specification.

**Input Code/Spec:**
```{CODE_OR_SPEC}```

**Target Tech Stack & Framework:** {LANGUAGE_AND_FRAMEWORK}
**Mocking Strategy:** {MOCKING_PREFERENCES}
**Special Coverage Focus:** {COVERAGE_GOALS}

Please generate the test suite following these strict guidelines:
1. **Happy Path Tests:** Validate standard expected behavior with realistic inputs.
2. **Edge Cases & Boundary Conditions:** Test null/undefined values, boundary limits, empty collections, and unexpected data types.
3. **Error Handling & Failure Modes:** Assert that correct exceptions are thrown, errors are handled gracefully, and network/dependency failures are covered.
4. **Clean Code Structure:** Use the standard AAA (Arrange-Act-Assert) pattern, clean setup/teardown (`beforeEach`/`afterEach`), and explicit test names clearly stating intent.
5. **Mocks & Spies:** Provide realistic, inline mock implementations for all external dependencies or services.

Return production-ready code with minimal explanation, followed by a bulleted checklist of all test scenarios covered.

WHEN_TO_USE:
Use this prompt when building new features, refactoring legacy code, or preparing code for pull request review. It is ideal for developers who want to generate robust unit or integration test suites that cover obscure edge cases without spending hours writing repetitive boilerplate code.

EXAMPLE_INPUT:
{CODE_OR_SPEC}:
```typescript
async function processPayment(userId: string, amount: number, currency: string, paymentGateway: PaymentGateway) {
  if (!userId || amount <= 0) throw new Error("Invalid payment parameters");
  const user = await User.findById(userId);
  if (!user || !user.isActive) throw new Error("User unauthorized or inactive");
  const transaction = await paymentGateway.charge({ amount, currency, customerId: user.gatewayId });
  if (transaction.status !== "succeeded") {
    await AuditLog.recordFailure(userId, transaction.errorCode);
    throw new PaymentFailedError(transaction.errorMessage);
  }
  await AuditLog.recordSuccess(userId, transaction.id);
  return transaction.id;
}
```

{LANGUAGE_AND_FRAMEWORK}: TypeScript with Jest

{MOCKING_PREFERENCES}: Mock `User.findById`, `AuditLog`, and `paymentGateway` using `jest.fn()`

{COVERAGE_GOALS}: Focus heavily on invalid inputs, inactive user states, payment gateway API errors, and verifying correct audit logging side-effects.

EXAMPLE_OUTPUT_SUMMARY:
The model generates a single, fully typed Jest test file with a clean `describe('processPayment')` block containing 8 distinct test cases. It sets up proper mocks for `User`, `AuditLog`, and `paymentGateway`, covering happy paths, thrown parameter errors, inactive user scenarios, failed transaction handling, and asserts exact mock call arguments using `toHaveBeenCalledWith`.

PRO_TIPS:
- Provide interface or type definitions inside `{CODE_OR_SPEC}` to ensure generated mocks match your exact type contracts.
- Specify exact assertion styles (e.g., "Use React Testing Library with `userEvent` instead of `fireEvent`") if using UI frameworks.
- Ask the prompt to include custom test data factories (e.g., `buildMockUser(overrides)`) to make long-term test maintenance easier.
