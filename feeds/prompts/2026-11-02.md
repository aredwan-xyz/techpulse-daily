PROMPT_TITLE: Comprehensive Test Suite Generator

THE_PROMPT:
You are an expert QA Engineer and Test Architect. Your task is to generate a comprehensive, production-ready test suite for the provided code or feature description.

Target: {CODE_OR_FEATURE}
Tech Stack / Framework: {TECH_STACK}
Testing Levels Required: {TESTING_LEVELS} (e.g., Unit, Integration, E2E, Edge Cases, Security)

Please structure your response as follows:
1. **Test Strategy Summary**: Brief overview of the approach, covering happy paths, edge cases, and failure modes.
2. **Test Cases**: A categorized, numbered list of test scenarios including preconditions, test steps, and expected results.
3. **Executable Code**: Fully written, idiomatic test code using {TECH_STACK}, complete with necessary mocks, stubs, and assertions. Include setup and teardown logic where applicable.
4. **Coverage Analysis**: Mention potential blind spots, race conditions, or environmental factors to watch out for.

Ensure the code is robust, clean, follows best practices (e.g., AAA pattern - Arrange, Act, Assert), and requires zero placeholder implementation.

WHEN_TO_USE:
Ideal for rapidly generating rigorous, enterprise-grade test suites for new functions, classes, or user flows. Best used when you want to ensure high test coverage, including tricky edge cases and failure modes, without writing every test from scratch.

EXAMPLE_INPUT:
CODE_OR_FEATURE: A user registration function that validates email formats, enforces a minimum 8-character password with at least one number and symbol, hashes the password via bcrypt, and saves to PostgreSQL.
TECH_STACK: Jest & TypeScript
TESTING_LEVELS: Unit tests, Edge Cases, and Mock Integration tests

EXAMPLE_OUTPUT_SUMMARY:
Produces a structured test strategy, a bulleted list of 10+ specific test scenarios, production-ready TypeScript/Jest test code with full mocking of the database layer and bcrypt, and a coverage risk assessment.

PRO_TIPS:
- Specify if you are using a particular testing library or assertion style (e.g., Supertest, Chai, Jest mocks) in the TECH_STACK variable.
- Request specific negative tests or security scenarios (like SQL injection or weak passwords) by explicitly mentioning them in the TESTING_LEVELS field.
- Feed the generated test code directly into your codebase and run it; edge-case mocking provided is usually 90% ready out-of-the-box.

WORKS_WITH: Claude · GPT-4 · Gemini
