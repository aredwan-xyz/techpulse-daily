## 🎯 The Core Idea
PlayCraft is an automated system that designs engaging video games by pairing two AI agents in a continuous loop: one plays the game, and the other redesigns it based on the player's experience. By simulating how human players learn and master a game, the system automatically tweaks difficulty and mechanics until the game is actually fun.

## 🔍 The Problem They Solved
While modern AI can easily write code for playable games, it has no intuition for whether those games are actually fun or properly balanced. Traditionally, crafting a rewarding game feel requires hundreds of hours of manual human playtesting to find the sweet spot between boringly easy and frustratingly hard. 

## 💡 The Key Innovation
Instead of analyzing raw code or basic statistics, PlayCraft relies on a vision-based agent that "playtests" the game through visual inputs just like a human. After each play session, this agent generates detailed self-reflection reports outlining its progress, decisions, and points of frustration. ## 🎯 Prompt of the Day


PROMPT_TITLE: Production-Ready Technical Documentation Architect

THE_PROMPT:
You are a Senior Technical Writer and Developer Advocate. Transform the provided raw technical information, code snippets, or architecture notes into clear, production-ready technical documentation.

**Documentation Subject:** {FEATURE_OR_SYSTEM_NAME}  
**Target Audience:** {TARGET_AUDIENCE} (e.g., Backend Engineers, API Consumers, Junior DevOps)  
**Primary Goal:** Enable readers to understand, implement, and troubleshoot this system efficiently.  

**Raw Technical Inputs & Notes:**  
{TECHNICAL_DETAILS_OR_CODE}  

**Context & Scope:**  
- **Prerequisites:** {PREREQUISITES_OR_DEPENDENCIES}  
- **Primary Use Cases:** {PRIMARY_USE_CASES}  

**Required Output Structure (in Markdown):**  
1. **Overview & Purpose**: High-level summary (1-2 paragraphs) explaining what this is and why it exists.  
2. **Prerequisites & Environment**: List required dependencies, permissions, and minimum versions.  
3. **Quickstart / Step-by-Step Implementation**: Sequential, executable steps with clean code blocks.  
4. **Architecture & Data Flow**: Concise breakdown of how components interact (include an ASCII diagram if applicable).  
5. **Code / Configuration Reference**: Production-ready, copy-pasteable code snippets with inline comments.  
6. **API / Parameter Reference**: Table columns for Parameter, Type, Required (Y/N), Default, and Description.  
7. **Troubleshooting & Edge Cases**: Table of Common Error/Symptom -> Root Cause -> Resolution.  

**Tone & Style:** Concise, imperative voice ("Run", "Configure"), precise technical terms, zero fluff.

WHEN_TO_USE:
Use this prompt when converting unorganized code snippets, pull request descriptions, architecture decision records (ADRs), or developer notes into standardized documentation. It is ideal for building internal developer docs, external API guides, software SDK guides, or open-source README files.

EXAMPLE_INPUT:
**FEATURE_OR_SYSTEM_NAME:** Redis-based Distributed Rate Limiter Middleware  
**TARGET_AUDIENCE:** Senior Node.js Backend Developers  
**TECHNICAL_DETAILS_OR_CODE:**  
We built a sliding-window rate limiter using Redis sorted sets (ZADD, ZREMRANGEBYSCORE). It wraps Express routes. Key file is `rateLimiter.ts`. Config takes `windowMs` (default 60000) and `maxRequests` (default 100). If Redis goes down, it defaults to fail-open mode and logs a warning to Datadog so we don't break user traffic. Throws HTTP 429 when limit exceeded with header `Retry-After`.  
**PREREQUISITES_OR_DEPENDENCIES:** Node.js v18+, Redis v6.2+, ioredis client npm package  
**PRIMARY_USE_CASES:** Protecting public REST endpoints from denial-of-service and abusive scraping.

EXAMPLE_OUTPUT_SUMMARY:
Produces a complete, structured Markdown document with a clear technical overview, an ASCII diagram of the Redis sliding window logic, a copy-pasteable Express middleware code snippet, a parameter matrix table, and a troubleshooting table detailing edge cases like Redis fallback behavior.

PRO_TIPS:
- Raw developer notes or git commit messages can be dumped directly into `{TECHNICAL_DETAILS_OR_CODE}` without pre-formatting.
- Explicitly state key edge cases (e.g., "fail-open on Redis timeout") in the input to ensure safety guarantees are documented clearly.
- Follow up by asking the AI to generate unit test samples or a OpenAPI/Swagger definition based on the output.

### What to Do When Vulnerability Feeds Go Down

When central databases like the NVD experience downtime, your security workflow shouldn't come to a halt. Take these proactive steps today:

1. **Run Local & Offline Security Audits:** Rely on your local build tooling to catch known issues. Use package-level auditors integrated into your CLI:
   * **Node.js:** `npm audit` or `yarn audit`
   * **Python:** `pip-audit`
   * **Rust:** `cargo audit`
   * **Containers:** `trivy image <image_name>` or `grype <image_name>`
2. **Review Lockfiles for Drift:** If you are building container images or deploying services today, ensure your lockfiles (`package-lock.json`, `poetry.lock`, `Cargo.lock`) are enforced so unvetted transitive dependencies aren't pulled in dynamically during downtime.
3. **Check Language-Specific Advisory Feeds:** Maintain bookmarks for vendor-specific security boards (such as the [GitHub Advisory Database](https://github.com/advisories) or [OSV.dev](https://osv.dev/)), which often remain accessible when central aggregators are offline.

RESOURCE_TITLE: GraphRAG
RESOURCE_URL: https://github.com/microsoft/graphrag
RESOURCE_SOURCE: Microsoft

WHY_NOW:
As standard vector-based RAG struggles with complex questions requiring synthesis across disparate documents, knowledge graph-enhanced RAG has become the industry standard for enterprise-grade applications. Microsoft's GraphRAG implementation provides a production-ready blueprint for shifting from simple similarity search to global, relationship-aware context extraction.

WHAT_YOULL_LEARN:
- How to automatically extract knowledge graphs (entities, relationships, and claims) from unstructured text using LLMs
- Hierarchical community detection algorithms (using Leiden) to summarize datasets at multiple levels of abstraction
- Global search techniques that answer macro-level questions about an entire corpus rather than just local document matching
- Prompt engineering patterns optimized for graph-based context injection and reasoning

WHO_ITS_FOR:
Backend engineers and AI architects who have hit the limits of naive vector search and need to build systems capable of holistic document understanding and multi-hop reasoning.

TIME_INVESTMENT: 4 to 6 hours to clone, run the end-to-end pipeline on sample data, and inspect the core indexing prompts.

BEST_QUOTE_OR_HIGHLIGHT:
"GraphRAG unlocks the ability to answer 'global' questions over a massive text corpus—questions that require understanding the dataset as a whole, which traditional vector RAG fundamentally cannot do."

Clone the repository, run the quickstart tutorial on a custom text file collection of your own, and compare the global search outputs against a traditional vector-search baseline of the same data.
