## What Is It?
Ruff is an extremely fast Python linter and code formatter written in Rust, designed to replace Flake8, Black, isort, and dozens of other tools in a single executable.

## The Problem It Solves
Python tooling has historically been slow and fragmented, forcing developers to chain together Flake8, Black, isort, and pyupgrade in their CI and pre-commit hooks. This resulted in laggy IDE feedback, long CI build times, and complex configuration files. Ruff replaces the entire patchwork with a single tool that runs 10 to 100 times faster.

## Why It's Worth 10 Minutes of Your Time
* **Instant feedback loop:** It lints and formats hundreds of thousands of lines of code in tens of milliseconds, eliminating IDE lag and CI bottlenecks.
* **Consolidates 5+ dependencies:** Replaces Black, isort, Flake8 (plus dozens of plugins like `flake8-bugbear`), and `pyupgrade` with a single `pyproject.toml` configuration.
* **Aggressive, safe auto-fixes:** Runs `ruff check --fix` to sort imports, strip unused variables, rewrite outdated syntax (like upgrading to Python 3.10+ union types), and format code without human intervention.

## Quick Start
```bash
# Install Ruff
pip install ruff

# Check for lint errors and auto-fix what's possible
ruff check --fix

# Format your codebase (Black-compatible)
ruff format
```

## Real-World Example
Running `ruff check --fix .` can automatically modernize legacy syntax, sort imports, and remove dead code in one pass:

---

### Proactive Defense: While Upstream Feeds Are Down

When external vulnerability reporting systems experience downtime, fall back on proactive internal hygiene:

1. **Run Local Audits:** Don't rely solely on automated nightly alerts. Run package-level vulnerability checks locally or in your CI pipelines (e.g., `npm audit`, `pip-audit`, `cargo audit`, or `govulncheck`).
2. **Review Pending Dependency Updates:** If you have open Dependabot/Renovate PRs, prioritize merging security-related patch releases after standard testing.
3. **Verify Lockfiles:** Ensure your package manifests use strict version pinning and committed lockfiles (`package-lock.json`, `poetry.lock`, etc.) to prevent non-deterministic builds from pulling unvetted minor/patch updates.

---

### Security Mindset
**Never trust an automatic PR just because it's automated.**  
When reviewing automated dependency upgrade PRs (like Dependabot or Renovate), always inspect the release notes, diffs, and package maintainer changes. Malicious typosquatting or compromised maintainer accounts often disguise supply-chain attacks as benign, routine version bumps.

RESOURCE_TITLE: WasmByExample
RESOURCE_URL: https://wasmbyexample.dev
RESOURCE_SOURCE: WasmByExample (Open Source / Aaron Turner)

WHY_NOW:
As WebAssembly expands beyond client-side browser optimization into server-side microservices, edge compute, and universal plugin architectures, understanding how high-level code compiles to Wasm is essential. WasmByExample provides instant, hands-on feedback across multiple source languages (AssemblyScript, C/C++, and Rust) without requiring any complex local toolchain installation.

WHAT_YOULL_LEARN:
- How to write and compile Rust, C/C++, and AssemblyScript into WebAssembly modules.
- How to import and export functions between WebAssembly modules and JavaScript runtimes.
- Memory management strategies and passing complex data types (strings, arrays) across the Wasm/JS boundary.
- Working with WebAssembly text format (WAT) and WebAssembly System Interface (WASI) primitives.

WHO_ITS_FOR:
Web developers, systems engineers, and backend developers looking to gain practical, code-first experience with WebAssembly across different source languages. It is ideal for anyone who wants to learn Wasm by tweaking live running code rather than reading dry specifications.

TIME_INVESTMENT: 1–2 hours

BEST_QUOTE_OR_HIGHLIGHT:
"WebAssembly is not meant to replace JavaScript, but to run alongside it—allowing developers to bring low-level performance, type safety, and existing language ecosystems directly to the web and beyond."
