## 🎯 Prompt of the Day


PROMPT_TITLE: Production-Ready PRD Generator

THE_PROMPT:
Act as a Principal Product Manager. Write a comprehensive, engineering-ready Product Requirements Document (PRD) based on the following input:

- **Feature/Product Name:** {PRODUCT_OR_FEATURE_NAME}
- **Core Problem to Solve:** {CORE_PROBLEM}
- **Target Persona:** {TARGET_USER}
- **Key Capabilities Needed:** {KEY_CAPABILITIES}
- **Constraints & Out of Scope:** {CONSTRAINTS_OR_OUT_OF_SCOPE}

Please structure the PRD as follows:

1. **Executive Summary & Problem Statement** (Why we are building this and the business impact)
2. **User Stories & Acceptance Criteria** (Format: *As a [user], I want [action] so that [benefit]*. Include explicit *Given/When/Then* acceptance criteria for each story)
3. **Functional Requirements** (Categorized logically and prioritized using P0/P1/P2)
4. **Non-Functional Requirements** (Performance thresholds, security, compliance, accessibility standards)
5. **Edge Cases & Failure Modes** (What can go wrong and expected system behavior)
6. **Out of Scope (v1)** (Explicitly listing non-goals to prevent scope creep)
7. **Success Metrics & KPIs** (Leading and lagging indicators to measure launch success)

Ensure the language is precise, unambiguous, and immediately actionable for software engineers and UX designers. Avoid vague phrases like "user-friendly" or "fast"—specify concrete behaviors and metrics.

WHEN_TO_USE:
Use this prompt when transitioning from a high-level feature concept to tactical execution. It is ideal for Product Managers, Tech Leads, and Founders who need to hand off detailed, unambiguous specifications to engineering and design teams without missing critical edge cases.

EXAMPLE_INPUT:
- **PRODUCT_OR_FEATURE_NAME:** One-Click Guest Checkout
- **CORE_PROBLEM:** Mobile cart abandonment is at 68% because forced account creation adds too much friction during impulse purchases.
- **TARGET_USER:** First-time e-commerce buyers browsing on mobile devices.
- **KEY_CAPABILITIES:** Checkout without creating an account, native Apple Pay/Google Pay integration, auto-fill address via browser, post-purchase optional account creation.
- **CONSTRAINTS_OR_OUT_OF_SCOPE:** Must comply with GDPR/CCPA. Out of scope for v1: Self-service guest order returns (guests must contact support), gift card payments.

EXAMPLE_OUTPUT_SUMMARY:
A complete, structured PRD featuring granular user stories with Gherkin-style (Given/When/Then) acceptance criteria, prioritized functional specs (P0-P2), non-functional compliance and speed requirements, detailed edge-case handling (e.g., email address already associated with an account), clear scope boundaries, and trackable success metrics.

PRO_TIPS:
- Provide specific technical constraints in `{CONSTRAINTS_OR_OUT_OF_SCOPE}` (e.g., "Must work with legacy REST API v2") for more accurate functional requirements.
- After receiving the PRD, ask the AI to "Convert Section 2 into Jira ticket markdown format" to instantly generate sprint backlog items.
- If you have design tokens or a specific tech stack, add a `{TECH_STACK}` bullet to the prompt input for tailored non-functional requirements.

WORKS_WITH: Claude · GPT-4 · Gemini

### Proactive Security Focus: Defending Without Feed Updates

When vulnerability feeds go down, your proactive baseline security keeps your applications safe. Use today's downtime to perform quick defensive hygiene across your repositories:

1. **Audit Local Dependencies:** Run your ecosystem's native vulnerability scanner (`npm audit`, `pip-audit`, `cargo audit`, or `go vuln check`) to catch flagged vulnerabilities already cached in your toolchain.
2. **Verify Lockfile Integrity:** Ensure all production builds are strictly using pinned versions via lockfiles (`package-lock.json`, `Cargo.lock`, `requirements.txt` hash pins) to prevent supply-chain drift.
3. **Review Third-Party Integrations:** Double-check API keys and secrets stored in your environments to ensure no credentials were accidentally checked into recent commits.

---

### 💡 Security Mindset Tip

**Practice Zero Trust at the Code Level:**  
Never assume data is safe just because it came from an internal microservice, a database, or an authenticated user. Validate, sanitize, and strictly type-check all incoming inputs at the boundary of your module—internal boundaries are just as critical as external ones.
