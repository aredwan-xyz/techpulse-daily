## 🎯 The Core Idea (2 sentences)
Video-Coder is an AI agent that generates controllable videos by writing and executing 3D graphics code to build a structural "draft" scene first. It then uses this 3D draft as a blueprint to guide a downstream video generation model in rendering the final, polished clip.

## 🔍 The Problem They Solved (2 sentences)
Standard text-to-video models struggle with precise spatial layouts, realistic physics, and fine-grained camera control, often resulting in visual warping or ignored instructions. Text prompts alone lack the precision needed when an application requires exact object positioning, consistent motion dynamics, or specific camera angles.

## 💡 The Key Innovation (2-3 sentences)
Instead of rendering pixels straight from text prompts, the authors trained an LLM agent using supervised fine-tuning and reinforcement learning to write executable 3D graphics code (like Blender scripts). This code generates a raw 3D animation that acts as a deterministic "skeleton," providing explicit structural and motion guidance directly to the video generator.

## 🛠️ Why Developers Should Care (2 sentences)
This framework introduces programmatic, deterministic control to generative video pipelines, allowing developers to manipulate timing, object placement, and camera tracks via code rather than guessing text prompts. ## What Is It?
SigNoz is an open-source, full-stack observability platform built natively on OpenTelemetry and ClickHouse. It provides a single dashboard to view application metrics, distributed traces, and logs, acting as a self-hostable alternative to tools like Datadog and New Relic.

## The Problem It Solves
Proprietary observability vendors often hit growing teams with astronomical, unpredictable monthly bills for trace and log ingestion. On the flip side, building an open-source observability stack traditionally meant stitching together Prometheus for metrics, Jaeger for traces, and Loki for logs—leaving developers to manage three backend databases and fragmented dashboards. SigNoz unifies all telemetry data into one fast interface using a single columnar storage engine.

## Why It's Worth 10 Minutes of Your Time
1. **Native OpenTelemetry standard:** Built from the ground up to consume OpenTelemetry data directly, preventing vendor lock-in for your application instrumentation.
2. **Powered by ClickHouse:** Uses ClickHouse as its storage backend, delivering blazingly fast aggregation queries and up to 10x better data compression than ElasticSearch.
3. **Seamless correlation:** Allows you to click directly from a spike in your p99 latency graphs straight to the exact distributed trace and correlated log line in a single click.

## Quick Start
```bash
git clone -b main https://github.com/SigNoz/signoz.git && cd signoz/deploy/
./install.sh
# Access the UI at http://localhost:3301 once containers are up
```

## Real-World Example
Configuring a Node.js application to auto-instrument and send traces directly to your local SigNoz instance:

```javascript
// tracing.js - Run with `node --require ./tracing.js app.js`
const { NodeSDK } = require('@opentelemetry/sdk-node');
const { OTLPTraceExporter } = require('@opentelemetry/exporter-trace-otlp-grpc');
const { getNodeAutoInstrumentations } = require('@opentelemetry/auto-instrumentations-node');

const sdk = new NodeSDK({
  serviceName: 'order-service',
  traceExporter: new OTLPTraceExporter({
    url: 'http://localhost:4317', // SigNoz gRPC collector address
  }),
  instrumentations: [getNodeAutoInstrumentations()],
});

sdk.start();
```

PROMPT_TITLE: The Technical Email Synthesizer

THE_PROMPT:
You are an expert technical communicator who excels at translating complex engineering concepts into clear, actionable, professional emails tailored to specific audiences.

Draft a professional email using the following input parameters:

- Audience: {AUDIENCE} (e.g., Executive Leadership, Non-technical Product Manager, Client, Internal Engineering Team)
- Primary Goal: {PRIMARY_GOAL} (e.g., Post-Mortem Incident Report, API Deprecation Notice, System Upgrade Request)
- Tone: {TONE} (e.g., Urgent yet reassuring, Formal, Direct, Collaborative)
- Raw Technical Notes: 
{RAW_TECHNICAL_NOTES}
- Action Required from Recipient: {ACTION_REQUIRED}
- Key Deadlines / Timeline: {DEADLINES}

Guidelines for the output:
1. Provide 2-3 subject line options (varying from direct to context-rich).
2. Begin with a 1-2 sentence "TL;DR" summary focused on business impact or immediate key outcomes.
3. Translate dense technical details into terms appropriate for the specified target audience without losing essential accuracy.
4. Structure the body using clear headers, bullet points, and bold text for critical metrics, risks, or dates.
5. End with an explicit Call-To-Action (CTA) clearly stating next steps, ownership, and deadlines.

WHEN_TO_USE:
Use this prompt when you need to send technical updates, outage reports, architecture change proposals, or product deprecation notices to stakeholders. It is especially useful when translating dense engineering notes into clean communications for business leaders or external clients.

EXAMPLE_INPUT:
- Audience: Non-technical Executive Leadership (VP of Product, COO)
- Primary Goal: Update on Redis cluster memory exhaustion outage and long-term fix proposal
- Tone: Professional, reassuring, and data-driven
- Raw Technical Notes: 
- 08:14 UTC: Redis primary node ran out of RAM (OOM killed) due to unindexed cache key buildup from the new search service.
- Caused 14 minutes of checkout failures (402 errors on /v2/checkout endpoint).
- Failover to replica triggered at 08:28 UTC.
- Hotfix deployed: Flush cache key pattern `search:temp:*` and cap TTL to 3600s.
- Need $2,500/mo budget increase to upgrade to Managed Redis Cluster with auto-scaling to prevent recurrence.
- Action Required: Approval for infrastructure budget increase.
- Key Deadlines / Timeline: Approval needed by Friday end-of-day.

EXAMPLE_OUTPUT_SUMMARY:
The prompt produces a structured email featuring multiple subject line choices, an executive TL;DR highlighting the 14-minute checkout impact and resolution, a non-jargon explanation of why the crash occurred, a bulleted breakdown of the permanent fix, and a clear budget approval request section complete with a Friday deadline.

PRO_TIPS:
- Paste raw, messy slack messages or incident terminal logs directly into `{RAW_TECHNICAL_NOTES}`—the prompt is designed to organize chaos.
- Explicitly set `{AUDIENCE}` to "Non-technical executive" if you want the model to convert technical terms (like OOM, TTL, Redis) into plain business impact language.
- Request an additional "Technical Appendix" section if you want to include deep technical specs at the bottom of the email for engineering recipients.

### General Security Advice: Operationalizing Dependency Security

When vulnerability databases experience downtime, automated scanner alerts may pause, but attacks do not. Use this time to reinforce your baseline security hygiene:

1. **Audit Your Lockfiles:** Ensure your project dependencies are pinned to specific, known-good versions rather than accepting floating ranges (e.g., `^1.2.3` or `*`). This prevents malicious or compromised downstream packages from automatically entering your builds.
2. **Review Open PRs for Dependency Updates:** Manually check pull requests bumping third-party libraries against project release notes and repository commit histories to spot suspicious package takeovers or typosquatting attempts.
3. **Run Local Software Composition Analysis (SCA):** Leverage cached engine updates from offline-capable scanners (e.g., `npm audit`, `cargo audit`, `trivy`, or `govulncheck`) to catch previously identified high-severity vulnerabilities in your pipeline.

---

### 💡 Security Mindset

**Treat lockfile changes with the same scrutiny as business logic.** 
When reviewing a Pull Request that updates `package-lock.json`, `Cargo.lock`, or `requirements.txt`, don't just gloss over the generated diff. Verify that the added or updated dependencies are expected, coming from trusted maintainers, and actually match the intent of the PR.
