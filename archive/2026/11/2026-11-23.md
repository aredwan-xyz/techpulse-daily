## 💡 Coding Challenge


TITLE: The Alternate Parity Splitter
DIFFICULTY: Easy
TOPIC: Linked Lists
ESTIMATED_TIME: 15 minutes

PROBLEM:
Given a singly linked list of integers, you need to "split" it into two separate lists: one containing nodes with even-valued data, and the other containing nodes with odd-valued data. You must maintain the original relative order of elements for both new lists. Return the heads of these two lists as a tuple or array.

EXAMPLES:
Input: 1 -> 2 -> 3 -> 4 -> 5 -> 6
Output: [2 -> 4 -> 6, 1 -> 3 -> 5]
Explanation: We traverse the list, moving even values to one chain and odd values to another, preserving their sequence.

Input: 10 -> 22 -> 33
Output: [10 -> 22, 33]

CONSTRAINTS:
- The number of nodes is between 0 and 1000.
- Node values are between -10^6 and 10^6.
- You must solve this in one pass.

HINT:
Use two "dummy" head nodes to act as anchors for the even and odd lists, and two "tail" pointers to keep track of the end of each new list as you traverse.

SOLUTION_PYTHON:
```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

def split_parity(head):
    even_dummy = ListNode(0)
    odd_dummy = ListNode(0)
    
    even_tail = even_dummy
    odd_tail = odd_dummy
    
    curr = head
    while curr:
        if curr.val % 2 == 0:
            even_tail.next = curr
            even_tail = even_tail.next
        else:
            odd_tail.next = curr
            odd_tail = odd_tail.next
        curr = curr.next
    
    # Terminate the new lists to prevent cycles
    even_tail.next = None
    odd_tail.next = None
    
    return even_dummy.next, odd_dummy.next
```

SOLUTION_JS:
```javascript
function splitParity(head) {
    let evenDummy = { next: null }, oddDummy = { next: null };
    let evenTail = evenDummy, oddTail = oddDummy;
    
    let curr = head;
    while (curr) {
        if (curr.val % 2 === 0) {
            evenTail.next = curr;
            evenTail = evenTail.next;
        } else {
            oddTail.next = curr;
            oddTail = oddTail.next;
        }
        curr = curr.next;
    }
    evenTail.next = null;
    oddTail.next = null;
    return [evenDummy.next, oddDummy.next];
}
```

TIME_COMPLEXITY: O(N) where N is the number of nodes in the list.
SPACE_COMPLEXITY: O(1) because we are rearranging existing nodes, not creating new data structures.

EXPLANATION:
We use two sentinel nodes (dummy heads) to avoid conditional checks for the head of the new lists. By maintaining two separate tail pointers, we can append nodes in constant time as we iterate through the source list once. This approach is optimal because it performs a single pass and requires only a constant amount of extra memory for the pointers.

FOLLOW_UP:
What if you were asked to group elements based on their position (odd indices vs. even indices) instead of their values? How would your pointer logic change?

# Rye

**Category:** Dev Tools
**Link:** [https://github.com/astral-sh/rye](https://github.com/astral-sh/rye)

[![Repo](https://img.shields.io/badge/View_on_GitHub-181717?style=flat-square&logo=github)](
https://github.com/astral-sh/rye)

---

## What Is It?
Rye is an experimental, all-in-one package and project management tool for Python created by Astral (the team behind Ruff). It aims to bring the seamless, cargo-like developer experience of Rust to the Python ecosystem.

## The Problem It Solves
Python dependency management has historically been fragmented across a dizzying array of tools like pip, virtualenv, poetry, pipenv, and pyenv. Developers previously had to manually juggle Python versions and wire together different tools for managing dependencies, lockfiles, and publishing. Rye fixes this by providing a single binary that handles everything from downloading Python itself to managing workspace environments.

## Why It's Worth 10 Minutes of Your Time
* **Zero-config Python installation:** Rye automatically downloads and manages the exact Python version your project needs without requiring system-wide pyenv setups.
* **Lightning-fast synchronization:** Powered by Astral's underlying technology and pip-tools concepts, it spins up virtual environments and resolves dependencies in seconds.
* **Unified workflow:** One consistent CLI (`rye init`, `rye add`, `rye run`) replaces the mental overhead of remembering different commands for different tools.

## Quick Start
```bash
# Install Rye
curl -sSf https://rye.astral.sh/get.sh | bash

# Create a new project and add a dependency
rye init my-project && cd my-project
rye add requests

# Run your code inside the managed environment
rye run python -c "import requests; print('Rye is working!')"
```

## Real-World Example
```toml
# pyproject.toml managed cleanly by Rye
[project]
name = "my-project"
version = "0.1.0"
dependencies = [
    "requests>=2.31.0",
    "click>=8.1.7",
]
requires-python = ">=3.11"

[tool.rye]
managed = true
dev-dependencies = [
    "pytest>=7.4.0",
]
```

## Who Should Use It
✅ Perfect for: Developers starting greenfield Python projects who want a modern, hassle-free toolchain without manual virtual environment management.
⏩ Skip if: You have complex, deeply customized legacy workflows heavily reliant on poetry or pipenv, or if you prefer assembling your own toolchain.

## The Honest Take
Rye brings much-needed sanity to Python project setup, though it's worth noting it's still evolving under Astral's experimental umbrella. Bottom line: if you love Cargo for Rust or npm for JS, Rye gives you that same cohesive workflow in Python.

4. **Impact / Risk:** What happens if we do (or don't) act?
5. **Next Steps & CTA:** Clear, bolded instructions with a deadline if applicable.

Produces a crisp, scannable email featuring a clear urgency-tagged subject line, a BLUF summary paragraph, bulleted technical context, and a prominent call-to-action that ensures rapid stakeholder sign-off.

While external vulnerability feeds are offline, take 10 minutes to run local automated checks on your repositories:

1. **Run Local Audits:** Execute your package manager’s built-in audit tool to catch known vulnerabilities in your dependency tree:
   * **Node.js:** `npm audit` or `pnpm audit`
   * **Python:** `pip-audit`
   * **Rust:** `cargo audit`

2. **Check Lockfiles:** Ensure your dependency lockfiles (`package-lock.json`, `Cargo.lock`, `requirements.txt`) are committed so build pipelines remain deterministic.
